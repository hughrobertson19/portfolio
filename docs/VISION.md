# Vision

Where aihugh.org is going. Keep this short; dated decisions live in STATE.md.

## Why it exists

aihugh.org is the page employers open to check Hugh's work before or after an application. Landing a job is Hugh's number one priority (Hugh, 23 Nov 2026), so the site has to be fast, working, accessible and current before he applies anywhere. Target roles: forward deployed engineer, deployment strategist, applied AI engineer, solutions or customer engineer, implementation lead (issue #1).

## What good looks like

1. **True.** Every claim about Hugh traces to a source doc or code. A clear line between what he learned and what he built. No result that is not on record.
2. **Current.** Finished builds from Hugh's other repos (the guest page pilot, Funding Radar, the Chicago Swans app) appear as short write ups: the problem, what was built, for whom, the result on record.
3. **Shows how Hugh works.** His strength is designing the user experience and adding a game layer on top of what exists, for example the staff contest in the guest page pilot. The site shows this as a strength, backed only by built work on record (Hugh, 23 Nov 2026, issue #2).
4. **Fast and accessible.** One static page, no framework, no third party scripts. Lighthouse 100 on mobile and desktop, no axe violations at phone and desktop widths in light and dark (baseline 24 Nov 2026).
5. **Links work.** Every link opens a public page.

## Never

- No private repo details, client data, client staff names or guest data. The three source repos are private: describe what was built, never link or quote internals.
- Never name a former employer critically. Which roles appear on the page is Hugh's call (Career-Business STATE, External-claim guardrails); the fleet never adds one.
- Never "Founder" for Shayke; it is "an applied learning project" with no customers.
- Wording employers read (claims, titles, project write ups) never merges from the fleet. It goes to a pull request titled "NEEDS HUGH: copy". Wording about the UX and game design strength goes there too (issue #2).
- US English and no em or en dashes on the site.
