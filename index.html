How I keep AI agents honest

Shayke is an applied learning project: a sales assistant I've built with AI coding agents, in my own time, to learn how production AI systems are designed. No customers.

Once a number becomes the target, it stops measuring the work. Goodhart's law. If an agent can see or shape its score, it will learn to chase the score.

So I split the system in two. The agents that do the work sit on one side. The scorer that judges them sits in its own repo on the other side. Results cross the line as plain files, never as code the agents can call.

The agents

Do the work. Never import the scorer. Tests fail if their code tries to.

result files only

The scorer

Lives in its own repo. Headless agent sessions can't edit the golden test cases.

Then, every night at 3:30am, a separate evaluator plays simulated sellers against the latest product build, plus one adversarial tester whose job is to break it. Think of mystery shoppers who come in every night, one of them trying to cause trouble.

  • Checked 12 Oct 2026The product's test suite: 10,446 passed, 32 skipped.
  • Checked 12 Oct 2026The agents read results through files only; tests check that agent code doesn't import the scorer or name where scores are stored.
